# `log_2 n` 比较动画设计

## 背景与目标

在 [`s4_3.construct()`](BusyBeaver/s4_ConcreteComparison.py:534) 的这一段落中，主公式 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) 已经被推到观众注意力的中心，后续原流程会直接进入三个局部高亮矩形 [`rect_n_1 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:889)、[`rect_n_2 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:894) 与 [`rect_c = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:899)。

新增动画的目标，是在进入这些局部高亮之前，用一段短而清楚的右侧临时图像说明一个直观事实：当 `n` 足够大时，`y=n` 会稳定压过 `y=log_2 n + C`。这段说明服务于 [`"BB"(n) >= "BB"(log_2 n + C)`](BusyBeaver/s4_ConcreteComparison.py:869) 这一层比较关系，作用是帮助观众理解，而不是替代主公式本身。

整段设计围绕两个原则展开。第一，主公式仍然是主体，右侧图像只是临时说明。第二，新增段落结束后，后续高亮与化简流程要按原构图无缝继续。

## 插入点

插入区间固定在 [`self.play(...)`](BusyBeaver/s4_ConcreteComparison.py:876) 之后、[`rect_n_1 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:889) 之前。新增内容只能落在这个局部范围内，不能向前后扩散到无关段落，也不能改写后续依赖 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) token 索引的结构。

这一段现有锚点代码里包含 [`self.camera.anim.points.move_to(UP)`](BusyBeaver/s4_ConcreteComparison.py:885)。已批准方案明确要求新增动画不使用相机位移，因此实际实现时需要在同一局部范围内处理这一动作，使整段说明通过对象布局与图像态切换完成，而不是通过镜头移动完成。

原有 [`self.forward(1.5)`](BusyBeaver/s4_ConcreteComparison.py:887) 可以并入新增段落的开场节奏中使用，也可以缩短为更适合新流程的停顿时长；这段空白不宜原样保留过长，否则会削弱插入段的连贯性。

## 视觉布局

主公式 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) 需要始终留在画面左侧主视区，视觉权重高于右侧临时图像。右侧图像应集中排布在坐标轴附近，尽量利用右半幅空间，不额外在左侧铺开说明文字。

右侧临时图像至少包含六类元素：坐标轴、连续函数 `y=n`、连续函数 `y=log_2 n` 及其平移版本、竖直平移箭头、短暂停留的偏移标签 `+1` / `+2` / `+3`、最后收束出的 `log_2 n + C` 与结论文字。

`y=n` 需要从开场到结束一直保留，作为稳定参照。`log_2 n` 与其上移版本负责表达比较关系的变化。短暂标签应靠近右侧图像，不应飘到主公式附近。最后的一般式与结论文字也应留在坐标轴周边，形成从具体示例到一般结论的收束。

如果当前主公式居中位置与右侧图像发生明显拥挤，可以对 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) 做一次轻微整体位置调整；不过这类调整只能作用于整体对象，不能拆解或重建公式，而且在右侧临时图像退场前必须恢复到后续高亮所依赖的位置。

## 动画流程

### 1. 开场建立参照

右侧坐标轴、`y=n` 和 `y=log_2 n` 先一起入场。开场动作要简洁，重点是迅速建立“线性函数”和“对数函数”之间的对比关系。此时不出现结论文字，也不出现一般式，画面只保留最基础的比较图像。

### 2. 第一次上移演示

第一轮演示按固定流程展开。竖直箭头先出现，明确表示这是沿 `y` 方向的平移；随后 `log_2 n` 过渡为 `log_2 n + 1`；曲线到位后短暂停留 `+1` 标签；最后箭头退场。`+1` 标签的停留时间只需要让观众完成识别，不宜拖长。

### 3. 第二次上移演示

第二轮继续沿用同一流程。竖直箭头再次出现，`log_2 n + 1` 过渡为 `log_2 n + 2`，随后短暂停留 `+2` 标签，再让箭头退场。

这一轮开始可以切换到更大的右侧观察窗口。窗口变化不通过相机或原地反复缩放实现，而是通过预定义图像态之间的形状匹配式变换来完成，让观众感到“看得更全”，同时保持对象状态清楚。

### 4. 第三次上移演示

第三轮继续重复同一节奏。竖直箭头出现后，`log_2 n + 2` 过渡为 `log_2 n + 3`，再短暂停留 `+3` 标签，最后让箭头退场。

如果前两轮已经进入较大的观察窗口，这一轮可以继续使用该窗口；如果前两轮只用了两套图像态，这一轮可以进入最远的一套图像态。无论采用两套还是三套图像态，逻辑都要保持一致：窗口变大来自完整图像态之间的变换，而不是镜头运动。

### 5. 从具体偏移收束到一般式

在三次具体演示之后，右侧图像要从 `+1`、`+2`、`+3` 收束为一般式 `log_2 n + C`。这个阶段需要让观众明确看到：前面的三个偏移量只是代表性的例子，真正要表达的是“无论加上一个固定常数，增长速度仍然远慢于 `n`”。

随后出现结论文字 `n > log_2 n + C`，并明确补上“`n` 足够大”这一条件。一般式与结论文字的停留时间应明显长于中间的 `+1`、`+2`、`+3` 标签，让收束结果成为这一段的视觉终点。

### 6. 退场与回接

新增的右侧临时图像整组淡出，不回放逆向动画，也不逐个回收中间状态。退场结束后，画面应立刻回到只保留主公式 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) 的状态，并顺畅接上后续的 [`rect_n_1 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:889)、[`rect_n_2 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:894)、[`rect_c = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:899) 以及随后的化简流程。

## 对象组织策略

主公式 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) 必须继续使用原对象。新增段落不能复制一份新公式来替代它，也不能通过重新排版改变它的 token 结构。任何位置调整都只能作用于整条公式对象。

右侧临时图像建议组织为一个独立临时组，生命周期从开场入场开始，到整组淡出结束。这个临时组内部可以再分为三个层次：稳定层、演示层、收束层。

稳定层包含坐标轴与 `y=n`，它们负责维持参照框架。演示层包含当前版本的 `log_2 n + k` 曲线、当前轮次使用的竖直箭头、以及当前短标签。收束层包含最终的一般式 `log_2 n + C` 与结论文字，它们只在最后阶段出现。

右侧图像需要预先定义两到三套完整图像态。每一套图像态都应包含完整的坐标轴、`y=n` 和当前版本的对数曲线，必要时也包含对应的说明文字。状态之间通过形状匹配式变换衔接，这样既能表达“观察窗口变大”，也能避免同一组对象在连续缩放后出现锚点混乱、比例漂移或残留痕迹。

`y=n` 在视觉上始终充当稳定参照，即便它在不同图像态中会通过整体变换参与过渡，观众看到的效果也必须是“参照线保持稳定”。`log_2 n` 及其平移版本则通过完整图像态之间的变换完成衔接。

`log_2 n` 的绘制定义域必须从正数开始。坐标轴范围、采样起点和曲线端点都需要避开 `x=0`，从而避免对数奇点带来的视觉错误。

## 兼容性约束

后续局部高亮直接依赖 [`text_bb_ge_2f["n", 0]`](BusyBeaver/s4_ConcreteComparison.py:890)、[`text_bb_ge_2f["log_2 n", 0]`](BusyBeaver/s4_ConcreteComparison.py:895) 与 [`text_bb_ge_2f["C"]`](BusyBeaver/s4_ConcreteComparison.py:900)。新增段落如果破坏 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) 的原对象或 token 结构，这三个高亮就会失效。

后续化简流程还依赖 [`text_bb_ge_2f[">= \"BB\"(log_2 n + C)"]`](BusyBeaver/s4_ConcreteComparison.py:942)、[`text_bb_ge_2f["\"BB\"(n)"]`](BusyBeaver/s4_ConcreteComparison.py:944) 与 [`text_bb_ge_2f[">= 2f(n)"]`](BusyBeaver/s4_ConcreteComparison.py:944) 的索引结果。新增段落不能通过替换公式对象来实现任何视觉效果。

新增段落不能留下任何右侧临时对象残留，也不能留下箭头、短标签、辅助文字或隐藏状态未清理的对象。退场完成后，后续逻辑应面对一套干净、可预测的场景状态。

新增段落不能引入额外的相机状态变化。整段说明的“放大观察范围”只能由右侧图像态切换承担。

## 实现边界

实现范围限定在 [`s4_3.construct()`](BusyBeaver/s4_ConcreteComparison.py:534) 内靠近插入点的局部片段。可以在这一局部范围内增加临时对象、局部位置调整与时间控制，但不抽离全局 helper，不修改其他场景类，也不触碰无关对象的生命周期。

这份设计只为后续实现提供结构化约束。真正落地时，需要把所有新增对象都限制在当前场景局部作用域内，并确保它们不会影响后续段落继续使用已有对象引用。

## 验收标准

新增段落实际插入在 [`self.play(...)`](BusyBeaver/s4_ConcreteComparison.py:876) 与 [`rect_n_1 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:889) 之间，且后续三处高亮与后续化简能够按原顺序继续执行。

主公式 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780) 在整个过程中保持原对象身份与 token 结构不变，后续所有索引访问都能继续成立。

右侧图像完整呈现坐标轴、`y=n`、`y=log_2 n` 与其三次上移演示，并按照“箭头出现、曲线上移、短标签停留、箭头退场”的节奏完成三轮演示。

整段说明不使用相机位移。所谓观察窗口变大，通过两到三套右侧完整图像态之间的形状匹配式变换表现。

`y=n` 从头到尾都是稳定参照，`log_2 n` 的绘制定义域从正数起步，没有触碰 `x=0` 的奇点。

`+1`、`+2`、`+3` 只是中间过渡标签，最终会收束为 `log_2 n + C`，并明确给出 `n > log_2 n + C` 与“`n` 足够大”的结论。最终一般式与结论文字的停留时长明显长于中间标签。

新增右侧临时图像最后整组淡出，不回放逆过程。淡出后画面中不存在右侧残留对象，也不存在异常的相机状态或布局漂移。

## 风险与注意事项

当前锚点代码里的 [`self.camera.anim.points.move_to(UP)`](BusyBeaver/s4_ConcreteComparison.py:885) 与已批准设计存在直接冲突。实现时如果没有在同一局部范围内处理这一动作，新增段落即使本身不再调用相机动画，也会让最终效果偏离已批准方案。

右侧图像如果做得过大，主公式就会失去画面中心地位；右侧图像如果做得过小，三次上移与最终收束又会难以辨认。实现时需要优先压缩右侧图像的信息密度，而不是扩大其占屏比例。

图像态之间如果几何结构差异过大，形状匹配式变换可能出现扭曲感。各状态中的坐标轴、`y=n` 和对数曲线需要尽量保持一致的构成方式，从而让状态切换看起来像观察窗口变化，而不是对象被重新生成。

短标签与箭头都属于过渡元素，它们的生命周期要短而清楚。任何一个过渡元素停留过久，都会削弱最终一般式与结论文字的收束力度。

如果实施时为了给右侧图像让出空间而临时平移了 [`text_bb_ge_2f`](BusyBeaver/s4_ConcreteComparison.py:780)，那么在右侧整组淡出之前，必须让该公式恢复到后续高亮所依赖的位置；否则 [`rect_n_1 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:889)、[`rect_n_2 = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:894) 与 [`rect_c = SurroundingRect(...)`](BusyBeaver/s4_ConcreteComparison.py:899) 的构图会失去原有连贯性。
